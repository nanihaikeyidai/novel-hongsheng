## 一、提示词写法
- 优先用官方 `h3-prompt-writing`（Ref2VA 六段结构）；文戏另外叠加 `minimax-h3-2`，武戏另外叠加 `minimax-h3-3`。
- 标签门禁：`<Subject N>` `<Picture N>` `<Audio N>` `<Video N>` `(Sx)` `<d>[Chinese] ...</d>` 必须齐全且已解析；`(Sx)` 后直接接 `<d>`；每个说话单元都要完整重复音色基线；不写选项式语言（如“远景或特写”）。
- 主体用英文，对白和屏幕文字保留中文。
- 写下一段之前先参考上一段的定稿提示词。
- **开跑 vs 重跑**：初稿写完后可直接开跑，不用先等审核。
- **自测失败后禁止自动重跑**：先复盘提示词（哪没写死、时间轴/禁止项是否缺失），改完后把问题与改法汇报给 David，等确认后再开跑；禁止自测失败后无限自动重跑。**踩过的坑必须提炼成不含专有名词的泛化经验**（模板/三层归档/G 编号见 `成片自审与提示词复盘规范.md` §六），操作型经验追加到本文件对应章节，不能只留在复盘文件里。
- **🔒 一次反馈 = 一版修改 = 一次生成（2026-11-05 用户硬性收紧，币耗闸门，优先级高于上面两条）**：
  1. 收到一次修改反馈，**只允许改一版提示词、提交一次视频生成**；不得因自测不理想就自动接着出 v2/v3/… 连跑。
  2. 出片后先抽帧验收 + 复盘 + 汇报改法；**下一次视频生成必须先向 David 明确确认**，并同时报出**预计币耗**（金鱼 15s / 1.5MP 实测 379–425 币/次）与这版要解决的具体问题，得到「可以生成 / 跑 vN」才提交。
  3. 用户已在需求里明说「重新生成 / 再跑一次」时，视为**该次已确认**，仍只生成一次；不得顺势再迭代第二版。
  4. **不烧币的处理不受限制且应优先**：抽帧验收、提示词复盘、规范回写、音频分窗增益、成片变速/动态增强、截成片末帧作参考图、改提示词但**不提交**。能用后期修到可用的，不重跑模型。
  5. 同一任务的队列/网络重试（421/805/queue 自动重试）不算「生成次数」；但同一需求**不得换提示词重开新任务**。
  - **反面账**：P14 v3→v7 五次重跑合计 **2008 币**（379 / 425 / 401 / 409 / 394），多为「改一版跑一次」的连续迭代。此后禁止。
- **🔁 踩坑 → 泛化经验 → 回写（2026-11-08 用户硬规则）**：复盘收尾不许停在「这次改了哪句」。每个坑按模板提炼 **G 编号经验**（删掉片段号／人物名／具体数值后仍成立，过三问），按三层归档落地：机制型 → `提示词避坑手册.md`（型/通则/约束块/自检），操作型 → **本文件**对应章节，资产型 → `参考图映射.md`／片段 `素材清单.md` 防呆标注；并登记 `成片自审与提示词复盘规范.md` §六.6 索引。复盘文件只存案例，规范文档才存经验——**下一次开工读的是规范文档**。此动作属不烧币处理，不受生成额度限制。
- **🔬 新配置首跑新任务先过最小样例（2026-11-11，G07）**：一套新工作流／新参数**第一次**用于一类新任务（如本地梅林 0.5MP/8步 首次跑高速武戏），先跑「1 镜＋1 动作＋同一套参考图」的最小样例，抽 3 帧看「场景出现／动作发生／人物对」，三项有两项不成立就先修配置或提示词长度，**不许直接上多镜正式稿**。最小样例与正式稿都算生成次数，仍受一次反馈一次的闸门约束。反例：EP06 6-1a v1 直接上 5 镜 2670 字符，8.3 分钟后发现整段场景动作没进 conditioning。
- **📏 提示词长度预算要连参考图像素一起算（2026-11-11，G08）**：ref2va／多图参考类节点的**文本与参考图共用同一个多模态上下文窗口**，预算 = 文本 token + 参考图 vision token。硬规则：① 以模板默认提示词为基线（本地梅林 `本地梅林模板_SparkON_0.5MP_15s_dmad.json` 节点 263 默认 **1185 字符**），新稿控制在 ±20%；② **场景与动作放文本前部**，主体定义压成短句后置；③ 参考图统一预缩放到生成分辨率量级（960×544）、去掉多视图拼图；④ `ref_image_size` 优先 `match`（`max` 会把原尺寸图整个塞进 Qwen3-VL，参考图 token 每一步都在；改模板参数须用户确认，因「不改工作流」硬规则）；⑤ `negativePrompt` ≤10 条且不写具体错误形态。判据：**人物锚全对但场景动作全丢 = 上下文预算超支**，不是模型画错。
- **🔊 本地梅林音轨是模型自生成的（2026-11-11，G04 变体；2026-11-18 补日语实测）**：模板音轨来自 `VAEDecodeAudio`（节点 115/254），没有外部音轨输入也没有静音开关。提示词写「全程无人声／禁止对白」**压不住**，实测 ASR 仍识别出 3 段中文乱语。本地梅林出片一律**后期替换整条音轨**为合成环境音，不靠提示词层；此条并入既有 G04「提示词层保不住的属性降级到后期层」。
  - ⚠️ **2026-11-18 日语翻车（批量脚本违反本条）**：EP06 全本批量脚本 `batch_ep06_full_meilin.py` 12 段全部用「口型『中文台词』／有人声对白」写法，想靠提示词让梅林说中文，结果 S04 整段 **日语**（ASR lang=ja p=0.89），其余段中文台词大量串音乱码（"小安娜"→"小安哪"）。S04 v2 样片即使写死「无对白、无人声说话、无旁白」+ negativePrompt 禁字幕，ASR 仍 lang=ja p=0.96。**结论：本地梅林无法用提示词指定Speaking语言，写中文台词＝白写**。凡本地梅林片段，**不得**在提示词里写「口型『台词』」或「说中文」来指望音轨；正确做法＝提示词只管画面口型动作，**音轨一律后期**（消人声留环境音，或重配音实验室合成中文）。H3 门禁的 `<d>[Chinese]</d>`+`(Sx)` 只适用于有 `<Audio N>` 音色槽的链路（云端金鱼 Ref2VA），本地梅林无音频槽不适用，别照搬。
- **🧊 连续失控 → 静态降级，别再加硬锁词（2026-11-14，G19）**：同一片段连续 2 版被判「方向不对／视角不对／人景不一致／控制不住」时，不要第三版继续堆 `DIRECTION LOCK / SPEED LOCK / MOTION UNITY LOCK / BANNED`。改法：① 上一版全部动作词物理清零（G16）；② 每个镜头只留 **1 个能用一帧静止画面回答**的状态变化（门推开 30°／笑容变大／车距缩短）；③ 时间推进靠**切镜**，不靠模型算物理；④ 写固定机位 + 柱子灯管停车线逐格同坐标，无速度线／运动模糊／跟拍；⑤ 连续两拍用同一张底图图生图、只改一个变量，作为「背景没动」的证据。⚠️ 用户明说「背景不用动」时，§五的 G17「背景按车速后退」**停用**，两套运动锁不能同写；K 型加速词一并清掉。⚠️ **2026-11-14 追加边界修正：只降动作链复杂度、不降速率，见下方 G23**（本条 G19 结论不改）。
- **🖼️ 连续改版 ≥2 次 → 先出宫格图确认镜头理解（2026-11-14，G20）**：争点是镜头／机位／方向／动静关系时，下一版**不直接提交视频生成**。先建 `分镜确认_6宫格/`，按时间顺序出 6 张分镜图 + 2×3 拼图（带中文镜头标签），写 `*_镜头理解_6宫格说明.md`（必含「用户原话逐条反推的验收判据」表，见 G15），文档与图上标注「仅出图，未提交视频生成」；出图废稿移 `_废稿/` 留对照。**宫格图不算一版视频、不占用「一次反馈＝一次生成」配额，也不消耗视频生成积分**（生图约 5–10 积分/张，远低于一次视频的 76–82 积分）。用户确认镜头理解后才写 v{n+1} 提示词；提交前仍须按 §一闸门报点数并取得确认。反例：同一片段连跑四版共约 238 积分，每版都在赌镜头理解。

- **🎯 参考图角度会被特写景别继承（2026-11-14，G21）**：人物参考图若是 3/4 侧／低头头肩裁切，只写 `FULL FRONT VIEW / shoulders square` 挡不住——特写会直接继承参考图角度（v4 蓝隼特写偏 3/4，车后远景反而完全正面）。改法：① 参考图行声明「只继承发色／剃纹／墨镜／服装，不继承拍摄角度」；② 特写镜写机位层硬锁 `CAMERA ON HIS CENTRAL AXIS, BOTH EARS VISIBLE, sunglasses lenses EQUAL width, nose bridge on the vertical center line`；③ 验收按景别分列判据，远景达标不等于特写达标（G15）；④ 换正面头肩参考图属改素材，须单独确认（G06）。
- **📐 「背景不动」要量化验收（2026-11-14，G22）**：用户要求「旁边背景不用动／固定机位」时，除目检拼图外，须对同机位 6–8 个时间点裁上部背景带（柱子／灯管／停车线，避开主体运动区）算相邻帧灰度平均绝对差（0–255）；第一个大差值通常是切镜，单独剔除，剩余均值 <10 才算背景锁生效。量化与拼图一起归档，不用单一指标下结论。v4 Shot 5 实测 `[50.08, 4.83, 6.50, 6.79, 7.79, 5.09, 2.37]`，切镜后均值 5.56。脚本 `check_ep06_6-1a_jinyu_v4.py::background_stillness`。
- **⚡ 静态降级 ≠ 全片静止（2026-11-14，G23）**：用户先说「背景不用动」后又说「动作要快／车速要快／加速撞／夸张速度感」时，**不要撤回背景锁，也不要保留静止张力**。改法：① 静止锁只写「柱子／灯管／停车线逐帧同屏幕坐标、无背景漂移」，把 `no speed lines / no motion blur` 改成「`SPEED LINES ONLY hug car body, wheel arches, wet floor, NEVER over pillars`」；② K 型加速锚点全开（`ACCELERATES HARD / SPEED LINES / motion blur / GROWS LARGER / SHRINKS FASTER / cuts get SHORTER / spokes BLUR into radial streaks`）；③ 开门写 `SNAP open IN ONE BEAT`，车距写「后半变化率大于前半」；④ 速度放主体尺寸变化率／轮转拖影／门角跳变／发衣后扬／短切镜，不放背景位移；⑤ 与 §五 G17 仍互斥，用户未撤回「背景不用动」就不写 `MOTION UNITY LOCK`；⑥ 声音换 `engine note RISING in pitch / tyre SCREECH`，别留 `quiet`。反例：v4 把 K 型词全列进提交脚本 `BANNED` →「慢吞吞开过去」。本条是 G19 的边界修正，不推翻 G19。
- **⚠️ 主体变大 ≠ 背景不动（2026-11-14，G24）**：G23 的「速度感与背景静止可共存」只在「主体在画面内缩放」时成立。模型实现 `GROWS LARGER / gap SHRINKS FASTER` 的默认方式是**机位前推**，机位一推柱子灯管必然透视位移；同一版里同时写 `SPEED LOCK` 和 `BACKGROUND LOCK(SAME screen coordinates)` 属自相矛盾锁，背景锁必失效。**二选一**：① 背景绝对不动 → 机位写死车外固定点，用同一底图图生图／后期层做尺寸阶跃（G19 图生图证据法）；② 真实冲刺感 → 按 §五 G17 写 `MOTION UNITY LOCK` 明说背景按车速后退，把背景差值列为预期。验收按 G22 量化，>20/255 且目检柱子位移就把「背景不动」判不达标，别用「看起来没动」糊过去。v5 实测 25.08–50.87/255（v4 静止版 2.37–7.79）。
- **👥 多主体同框逐个配图锚（2026-11-19，G25）**：出画几个主体就配几张人物参考图（`<Picture N>`），一个都不能少；只写一行文字描述的主体会被模型脑补成默认形象，**还会反客为主覆盖掉有图锚的人**。本地梅林 H3 `ref_images` autogrow 最多 9 槽，脚本 `--img4` → 节点 520 → `ref_image_3` 可动态加槽，别被模板默认 3 槽卡住。验收按「能否逐个数出 N 个可区分主体」判。反例：S04 v9 三人同框只给 2 图、陆沉仅一行文字 → 全片同一黑发白衬衫男模；v9b 补第 4 图后三人全对。
- **➕ 加图必须减字对冲（2026-11-19，G26，G08 的操作补充）**：新增一张参考图＝vision token 上涨，必须同步减一镜／压约 800 字符，把总量拉回该链路已跑通基线。合并相邻同类镜（如瞬移+掐脖合一镜）腾预算，省下的镜给真正要独立成镜的动作。实测 v9＝3 图/7 镜/5738 字符（失败）→ v9b＝4 图/6 镜/4925 字符（成功）。加图不减字＝把已贴顶的上下文挤爆。
- **🖼️ 拼贴人设图要写隔离句（2026-11-19，G27）**：用四格／多角度拼贴人设卡作参考图时，参考图行必须写 `Inherit exact face/hair/clothes ONLY, NOT the reference's multi-panel layout or camera angles`，否则素材的四格框／拍摄机位会被当视觉事实继承。有单张干净图优先用单张（G21）。抽帧确认成片没带出分镜格线。

## 三、语速与对白预算

- **Windows 的 curl 要关证书吊销检查（2026-11-12，G11）**：本机 curl 走 Schannel，访问外部 HTTPS 会报 `curl: (35) CRYPT_E_REVOCATION_OFFLINE (0x80092013)`，导致 `--check` / `get_node_info` / 提交 / 下载全链路以「Get node info failed: None」失败。确诊法：同域名跑 `curl --ssl-no-revoke -o /dev/null -w "%{http_code}"`，返回 200 即确认。修法：用 `subprocess.run` 包装器给所有 curl 命令统一注入 `--ssl-no-revoke`，**不改全局 skill 库**；同一包装器加 `encoding="utf-8", errors="replace"`，避免中文 stderr 触发 `UnicodeDecodeError` 把 stdout 变成 `None`。此报错不是密钥失效、也不是余额不足，别去轮换凭据或充值。
- **方向锁锚在「画内另一主体」，别锚在「画面深处／坡道／朝镜头」（2026-11-13，G14，J-3）**：EP06 6-1a 云端金鱼 v1 写 `nose always points INTO the depth toward the exit ramp`，方向挂在相机／场景坐标系上，多机位时每个镜头各自重建「深处」，成片从车尾拍、蓝隼成车后远处小人影，用户判「方向不对，车头要对着蓝隼」。v2 改成相对人物锚：`NOSE + BOTH headlights aim AT Lan Sun's chest` / `IN THE HEADLIGHT CONE` / `the strip of floor between bumper and his boots SHRINKS frame by frame` / `LOW three-quarter FRONT-SIDE` 两者同框，并在六标签与每个 Shot 行重复同一轴向（脚本断言 `AT Lan Sun` 出现 ≥6 次）。**自检问一句：机位换了，这句方向描述还成立吗？** 不成立就改成两个主体之间的可验关系。
- **验收判据从用户原话逐条反推，不抄自己的提示词硬锁（2026-11-13，G15）**：v1 复盘 10 项全 ✅ 归档，验收第 5 项写的是「车头方向锁（朝画面深处、笔直向前、不倒车）」——正是从 v1 提示词抄来的锁，与用户要的「车头对着蓝隼／加速撞上去／一拳掀翻」无关，形成自证闭环；用户一句「不合格」整版推翻，多花一次生成与点数。改法：验收表加「用户原话／剧本原句」一栏，每条要求翻成一个能用一帧画面回答的是非问题，抽帧覆盖每条判据，必要时另做专项拼图（如每秒一帧的方向／动态专项）。
- **「动态强／速度快」先删拖节奏字眼，再补 K 型锚点（2026-11-13，J-3 + K 型叠加）**：v1 提示词里 `MOTIONLESS` / `coasts straight FORWARD` / `rolls forward` / `fixed` 机位 / `Hold >=0.5s` 全是避坑手册 K 型明令禁止的「稳／慢」词，且一个加速锚点都没有 → 成片慢速平移。v2 照约束块 9 补 `ACCELERATES HARD / SPEED LINES / motion blur / GROWS LARGER / cuts get SHORTER`，提交脚本把 `coasts / rolls forward / MOTIONLESS / Hold >= / slow motion / freeze frames / gentle / steady / never break stride` 全列入 `BANNED` 断言。**这类问题归因是「未遵循既有规则」，不是新坑；改法照抄手册原文即可。** 同理「一拳把车整个掀翻」不能写成「拳压凹车头→车尾掀起→绕车头侧转」（成片就是压凹后侧倒），要写 `ONE SINGLE PUNCH → ENTIRE car LAUNCHED off the ground / all four wheels leaving / half-turn in mid-air`。

- **改动作要清零旧词、撞色定稿要写正向色卡（2026-11-13，G16/G18）**：用户把「一拳掀翻」改成「脚踢车」时，不能只在结尾镜写 KICK——人物定义里的 `Power is BARE FIST`、summary 的 `ONE SINGLE PUNCH`、上一版的 `half-turn in mid-air` 都要删到 0 命中，并把这些词写进提交脚本 `BANNED` 断言，否则模型在拳／脚之间摇摆出折中形态。同理，用户要「落地爆炸」但项目定稿是冷蓝灰单色（唯一暖色是帕斯卡的红酒）时，**不写「不要橙色火球」**，只正向写 `a WHITE-hot flash burst / a BLUE-WHITE shockwave ring / thick BLACK smoke billowing`；A 型否定句会把禁色概念放回潜空间。若用户要传统暖色火球，属光色定稿变更，须单独确认再改，别擅自二选一。
- **人景运动不一致要写「单一运动系统 + 切镜继承」（2026-11-13，G17）**：v2 锁了车的加速与方向，却没约束跳车人物和背景的相对速度，用户判「人和背景动运动不一致」。改法直接照 `05-workflow/pv素材/帕斯卡_vs_蓝隼_15秒武戏提示词.md`：`每次切镜只改变机位，必须继承上一镜的坐标、朝向、速度、受损状态`，再加 `characters, car and background share ONE motion system`（柱与车道线按车速后退、翻滚人物继承车动量、每 0.5–1s 一个新接触）。验收单独出「跳车段＋背景」逐帧拼图。武戏模板是现成骨架，不要自己另发明运动条款。
- **拼贴人设图作参考要写「不继承版式／机位」隔离句（2026-11-19，G27）**：四格／多角度拼贴人设卡自带的四格框、分镜线、拍摄机位属「内容口径」，会被模型当事实继承。参考图行写 `<Picture N> X: the FACE and CLOTHES from this reference — Inherit exact face/hair/clothes ONLY, NOT the reference's multi-panel layout or camera angles`。S04 v9b 的 `<Picture 4>` 用四格陆沉人设图（1254×1254）+ 隔离句，成片无四格框。有单张干净正面图时优先用单张（G21），拼贴图属退路。

## 八、台词 / 屏字时序（防错位）
来源：P09 v7–v13 自测迭代（至 2026-11-03）；G29 四层锁 2026-11-21 S05 v5 / S06 v4 补（避坑手册 H-b 型 + 约束块 12）。

- **【G29 每次生成必看】台词四层锁（一次说对，从源头杜绝乱说话/复读/字幕）**：
  1. **结构归位**：台词必须写在 `detailed_description` 说话镜，格式 `Lan Sun (S1), flat amused, speaks: <d>[Chinese] 原句</d>`；speaker 用 `(S1)/(S2)`，`<Audio N>` 只作音色参考。**绝不能把台词写进 `overall_soundscape`**——那是氛围描述段，写进去模型会念成无意义音节或渲染成字幕。
  2. **秒数锁**：按 ~7 字/秒反推字数对应的起止秒并写进说话镜（`17 chars at ~7/sec, ~11.0s -> ~13.5s`）。
  3. **说完闭嘴锁**：台词结束瞬间写 `LIPS LOCK: ZERO syllables, no second line/echo/added words/reply to film end`；`overall_soundscape` 的 `Avoid:` 里原样再列一遍（正写 + Avoid 双处）。
  4. **空窗用表演填**：说完到片尾的剩余秒数写 `SILENT acting ONLY`（冷笑／慢眨眼／凝视／特写持机），不留「等对方回话」的空窗——空窗会被模型补话。
  - **同音误识按剧本原句核对**：ASR「赤铜/邪悉/刘西伊能」实为「赤瞳/邪系/流系异能」，属识别误差不算乱说，不为它重跑。
  - ⚠️ **画面禁字幕的正解是强制声明**（`spoken dialogue = AUDIO ONLY, never rendered as on-screen text/watermark; NO visible text of any kind`），**不是删 `<d>` 台词**。此前「为避字幕删台词」是过度纠偏：音色参考还在、模型照样发声但没内容 → ASR 变无意义音节。写台词是对的，v2 出字幕是因台词塞错段落 + 无强制声明。

- **硬切后才说指定台词**：角色 A 镜头里禁止出现角色 B 的台词。例：门卫镜头只许「喂？」；「晚安」只能出现在硬切到沈默侧脸之后。
- **短句只说一次**：在 subject、summary、detailed、soundscape 四处都写 ONCE / no second；避免项再写「禁止第二遍」。
- **屏字先出文字参考图再喂视频**：技能字/屏幕文字（如「危险通话」）先由资产生成机器人出文字参考图，再作为图片参考喂进视频；不要只靠文生视频凭空出字。
- **说完再出屏字**：把「说话」和「出字」拆成两个 Shot。说话那一镜写死 `NO on-screen text yet`；下一镜写 `lips CLOSED, silent ≥1.5s` 之后才出现屏字。
- **正写 + Avoid 双保险**：时间轴正向写清因果（先 A 后 B），Avoid 再列「第二遍台词 / 错镜头出声 / 边说边出字」。
- **长静默持机易复读**（P09 v8→v9）：说完「晚安」后若侧脸持机静默拖太久（如拖到 12s+ 才切回），模型仍可能在尾段再念一遍。说完后写死 `ZERO spoken syllables / lips locked` 到片尾；出字保持 2–3s 后尽快切回（建议 ~10s）；Avoid 写 second/echo/repeat。
- **硬切前台词渗漏**（P09 v9→v10）：即使写了「晚安」只在硬切后、ONCE，模型仍可能把第一声叠到门卫镜头（v9 ASR ~3.6–4.6s 门卫画面已有「晚安」，硬切约 5.5s）。改法：①门卫全段 / Pre-HARD-CUT 写死 `ZERO「晚安」phonemes`（subject/summary/detailed/soundscape + Avoid）；②硬切后先 `lips CLOSED mute ~0.3–0.5s`，再开「晚安」；③「晚安」时间窗锁死在硬切之后（如 ~5.5–6.5s ONLY）；④Avoid 写 `any「晚安」before HARD CUT / before ~5.5s`。
- **门卫持机空窗会被模型「补对方回话」**（P09 v10→v11）：v10 门卫「喂？」只占 ~0.3s，之后持机静默约 1.5–2s 才硬切（~5.0s），模型把这段「电话那头」空窗当成该有回话，就把「晚安」填进门卫镜头（ASR ~3.7–5.1s），沈默段又说一遍；单靠 ZERO/Avoid 禁令压不住。另外晚安窗（5.5–6.5s）离硬切仅 0.5s、Shot 3 与门卫段文字结构相似，也易让音轨把台词前移。改法：①说话方台词说完**立刻硬切**，不留「等对方回话」的持机空窗（喂？~2.5–3.0s → 硬切 ~3.5s）；②提示词写 `no reply heard / guard never hears a reply`；③硬切后 mute 0.3–0.5s 再开口；④出字后切回的静默镜头也要短、写 ZERO speech。原则：**能删掉的空窗就删，别只靠禁令。**

- **回切后弹回说话角色仍会复读**（P09 v11→v12）：v12 把回切后贴耳静默改成立刻放下手机，前段「喂？」后硬切与第一声「晚安」+「危险通话」时序已过；但 ~8s 回切门卫后模型又在 ~11s 弹回沈默侧脸+屏字，并在 ~12.6–13.0s 补第二声「晚安」（分窗 ASR + RMS 峰）。改法方向：①出字后不要再给长尾段；可停在沈默静默/环境音或短空镜收束；②Avoid 写死 `no return to speaking CU after text / after ~8s`、`ZERO speech after first 晚安`；③自测必须分窗 ASR，不能只看全片 ASR（两声会被并成一段）。

- **回切门卫新台词也要 ONCE + 短尾**（P09 v13）：v13 在出字后硬切回门卫并加紧张回「你是谁！」；前半「喂？」→硬切→唯一「晚安」→「危险通话」+绿异能火均过，且未再弹回沈默说晚安。但分窗 medium ASR 显示「你是谁」仍念了两遍（~10.1–12.1s 与 ~13.3–14.7s）。改法：①回切后新台词同样写 ONCE / no second / no echo；②说完立刻闭嘴或短动作收束，不留 3s+ 贴耳空窗；③Avoid 写 `second 你是谁 / echo after first reply`。
- **绿异能火绑定屏字时机**（P09 v13）：「危险通话」出现时沈默手机旁起青绿异能光带（v13 ~6.5–8s 画面过关）；正写 `green energy WITH on-screen text`，Avoid 写 `green flame before text / green glow on guard phone early`。v13 门卫开场贴耳已见青绿光，属过早；**若重做**再把绿光锁在沈默出字镜（v13 已过关，不强制）。
- **耳侧光不洒身**（P09 v13）：接电话亮屏只贴耳朵一侧；正写 `screen glow only at ear / cheek edge` + Avoid `chest/torso phone light flood`。v13 门卫贴耳光较集中，沈默侧脸未大面积洒身。
- **P09 v13 已过关（2026-11-03）**：David 接受成片（含尾段「你是谁」念两遍）；后续 P09 **保持 v13**，不为「你是谁」复读单独重跑。绿异能火若重做，再把开场门卫侧的过早绿光锁死到沈默出字镜；当前过关版不强制改。

- **成片自测再交付**：抽帧 + 听音频（ASR）+ 核对口型/画面。核对①每句台词内容与出现次数；②是否叠在正确镜头；③屏字内容与出现时机（是否在台词结束之后）；④眼镜、手机朝向、门把手等硬约束。自测不过关：复盘提示词 → 汇报改法 → 等 David 确认后再重跑；不把未自测成片发给 David。

## 九、音效响度（2026-11-04 P14 v3 教训）
- 提示词写 `LOUD / piercing / high-decibel / dominant / louder than…` **不能保证成片音轨真的更响**：H3 音频在模型侧归一化，同一条提示词不同采样可随机差 1–6 dB。P14 v3 已写满响度形容词，全片仍比 v2 低 1.7dB、开场低 5.7dB。
- 要求「某音效更响」时的标准做法：提示词照写音色层次，验收改走**成片音轨后期分段增益**（音效段 +4~5dB，对白窗保持原电平，边界 80ms 平滑，逐点限幅、勿全局归一化），输出 48kHz AAC + faststart。
- 验收用分窗 RMS 对比（全片 / 对白窗 / 纯音效段 / 开场），并**重跑 ASR** 确认台词内容、次数没被改动。
- 不为了「模型原生更响」盲目重跑烧币：结果随机、提示词已到顶，后期更可控。详见 `全局文档/工作流规范/提示词避坑手册.md` I 型。
- **无对白片段先做音轨体检，再决定要不要后期替换（2026-11-12，G13）**：0 台词片段默认**不绑音频槽**（避免音色参考诱发乱语），但「没绑槽」不等于成片静音——EP06 6-1a 云端金鱼 0 音频槽仍输出 AAC 32kHz 立体声，逐秒 RMS −43.6～−15.8dB 且 10–11s 砸车 / 12–13s 砸地出现峰值，离线 ASR `segments=0`。出片后跑三项：`ffprobe` 查音频流、逐秒 RMS 看是否随动作起伏、离线 ASR 查乱语；**无音轨／纯静音／有人声乱语任一命中才做合成环境音替换**，三项都过就交付原音轨。别因为本地梅林 v1 出过自生成中文乱语，就给每段都预排后期替换。

## 十、场景光色与参考图污染（2026-11-06 P16）

## 十一、镜头动作拆分（2026-11-06 P16）
- **入口动作锁**：不要写「门打开」瞬时事件再配空场参考图——模型优先服从空场，人会凭空出现。改写为起点已含人：`ALREADY mid-stride entering frame … door still swinging shut BEHIND them`；禁止开场空建立镜。
- **同镜单动作锁**：一个 Shot 只承载**一个**主导肢体动作。特写若要保留，把门拉开 / 坐下等大幅动作放到上一镜收尾，或写成「手已在门把 / 门已开」的完成态。同镜「侧脸特写 + 拉开车门」会丢开门。
- **镜内勿再硬切**：同一 Shot 里再要求 HARD CUT，快速姿态（弯腰进车）易糊成色块；一镜一机位到底，旁动作用画外声带过。
- **独立特写镜的时长下限（2026-11-19，G28）**：需要单独验收的特写（红眼开眼、关键表情）留 **≥2s**；低于 2s 又紧随 POV／大动作这类强构图镜时，会被直接吞并抽不出来。真要极短闪帧就并进相邻镜开头动作里写，并在该时段密集抽帧验收；不足 2s 就别假装它独立成镜。反例：S04 v9b 红眼特写仅 1.5s，8.5–9.9s 抽帧全是 POV 背影，红眼镜被吞。
- **K 型奔跑效力上限（P16 再确认）**：只写 `sprint` 仍会直立快走；与 P14 同构。**不再堆提示词形容词**，出片后统一后期 `setpts=PTS/1.2~1.35` + `atempo`（必要时轻 `tmix`），与「一次反馈一版」闸门一致。

## 十二、无标识与多台词隔离（2026-11-07 P17）
来源：P17 v1 行车识破复盘；v2 提示词已写未提交。

- **无标识用正向锁，别写 BLANK 否命题**：`All … are BLANK` / `no readable text` 挡不住柱面「3」、地面车位字、方向盘徽标、伪汉字牌。改成材料正向 + 位置清单，例如：`Every concrete surface is PURE GREY CONCRETE with stains and shadows only — no digits, no pictograms, no arrows; the floor shows only wet reflections and tire smudges; the steering wheel hub is a PLAIN GREY ROUNDEL with nothing on it.`（覆盖柱 / 地 / 方向盘，不只 plate/dashboard。）
- **伪文字加强版（P15 起仍有效）**：招牌/安全出口写 `PLAIN blank surfaces — no characters of any language, no pseudo-glyphs`；绿出口标写成 `plain green rectangle with no marking`。
- **多台词硬隔离**：同一片段两句对白时，overall 层必须写死两句之间 ≥0.7s `TOTAL SILENCE`（lips closed, no breath），且 `NEVER spoken as one continuous sentence`；只在各 Shot 写各自时间窗不够，H3 会黏成一串，命令句失去冲击。
- **口罩+帽檐下的微表情细节**：冷汗等细节改落到**太阳穴 / 下颌线 / 颈侧**并给可数尺度（`two or three visible sweat drops … catching a hard highlight`）；写额头 `beads` 在遮挡+低照度下常退化成一道反光。
- **墨镜遮眼时表情上限**：wrap-around 墨镜挡住眉眼后，笑容只能靠嘴角；H3 默认给「从容/得意」。不重跑可后期 0.5s 定格微推 + 低频电流声加压；若要坚持墨镜又要更邪，提示词升到 `unhinged open-mouthed grin`（摘镜才是眼神邪的上限，偏离人设需用户点头）。

## 十三、本地重配音（0 币，2026-11-06）
路径：`05-workflow/重配音实验室/`（IndexTTS 2.5 + ComfyUI）。成片某一句情绪不对时，**优先本地重配再交付**，不为此烧 RH 币重跑整段。

- **低沉威胁靠音色+向量，不靠 text 情绪**：`text` 情绪模式常把 F0 抬到 ~200Hz（越写「气声/低声」越亮）；主推是原片切片作音色 + 冷静态向量（如 calm 高 / angry·disgusted 低）。`text` 若要用，`strength` 降到约 0.6，并验收 F0。
- **禁用 `[breath]` / `[quick_breath]`**：会被念成英文单词；气声改走后期 `whisperize.py`（谐波软化 + 气流噪声 + 近讲 EQ）。
- **对齐用能量包络，不用 ASR 时间戳**：ASR 可偏 +0.2s；`replace_line.py` 自动找真实起音。要「更轻」必须加 `--level-offset-db`（RMS 对齐会抵消生成时的轻），不要指望提示词形容词。
- **贴回成片**：画面 `-c:v copy`，**不加 `-shortest`**（会截掉末帧）；输出 48kHz AAC + faststart；自测视频流 md5 应与原片一致。
- 与「一次反馈一版」一致：音色/气声问题能本地修就不重跑金鱼。

## 十四、武戏能力投射物（2026-11-21 EP06 6-1f 泼酒成刃 v1–v2）
- **投射物数量写死就能数对**：`EXACTLY SEVEN slim tapered … BLADES in one fan row` 一次命中 7 枚；「多个」不写数，模型会给一大片。数量 + 形状（needle-thin / tapered / razor point）+ 材质（translucent like red glass）+ 朝向（aimed at X）四件套一起写。
- **「子弹时间」不用慢动作**：写 `Only the droplets themselves stop in the air; people and camera stay real-time`，悬停→拉长→收尖可在 1.5–2s 特写里完成，不触发整体慢放。
- **唯一暖色锁**：冷色场景里能力是红色时，加 `COLOR LOCK: X is the ONLY warm color`，并预先把参考图里的红灯/红晕物理擦掉（红灯会和能力抢色、诱发全片红光）。
- **小道具落地会复读**：「松手→杯子落地弹两下→裂开」写在台词同一镜里时，H3 会连掉好几只杯子。写成 `ONE object ONLY, falls ONCE, cracks and STAYS`，并把落地完成放在开口前，不和台词抢同一时窗。
- **格挡要写排他句**：只写「拳击碎第 N 枚」时仍会有刃从身体穿过；补 `every projectile either shatters on contact or flies past OUTSIDE the body`。v2 写了这句后，中景对打仍有刃穿过脸和胸口，须再加轮廓锁：`projectiles NEVER overlap the body silhouette / face / chest`。
- **电拳形态**：只写 `arcs on fists` 容易画成拳外电环；要贴皮电弧写 `thin jagged arcs crawling along knuckles and wrists, NOT rings`。这句须在**每个出拳镜头**（含中景/全景）重复写；v2 特写已贴腕，对打中景仍是拳外蓝光圈。斥力波可留在拳前，光圈不能套在拳上。
- **双句台词间隔**：写了 ≥0.7s TOTAL SILENCE 仍只得 0.22s；把第二句起点写成绝对时间（如 `starts at 13.0s`）并插入无声动作后，v2 间隔仍只有 0.36s，且第一句会提早约 1s 开口。更稳的是两句之间硬切到无口型动作镜，或预留后期把中间人声静音，不要只靠 overall 层静音窗。
- **单人动作镜要排他入画（v2 已验）**：需要「只看一个人做动作」时，写成该人特写，并写死 `OTHER CHARACTER IS NOT IN FRAME / does not appear`。用双人中景再指望构图躲开另一个人不可靠。v2 喝酒/泼酒两个特写（0–3.6s）另一人完全不入画。
- **格挡写身前力场，不要只写拳打中投射物**：远程拦截写成拳头打出可见斥力波/力场，投射物在拳前约半米撞上波阵面碎裂或弹开；只写「拳击中刃」时，模型容易画成拳打到人，或让人后退来「躲开」。
- **「不后退」要同时锁站姿**：只写 `FEET PLANTED / never move / HOLDS HIS GROUND` 时，人可能原地改成弓步。补 `upright stance, no lunge, knees not bent into a bow stance, feet stay under the shoulders`。
- **对打中未写动作的一方会即兴出招**：格挡镜如果只写进攻/格挡的一方，另一人可能伸手、出拳、把道具伸进力场，甚至多握出一只杯子。闲置一方要写死：站在哪一侧、只握几只道具、手放哪里、`NEVER punches / NEVER extends the prop`。
- **落地锁管不住对打镜里的道具分身**：`ONE object ONLY, falls ONCE` 能管住落地次数（v2 空杯只掉一次已验），但对打中景仍可能双手各出现一只。道具总数锁要写进所有出该道具的镜头，不只写落地那一镜。
