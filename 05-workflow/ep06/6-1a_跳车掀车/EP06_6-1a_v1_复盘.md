## 三、问题归因（回查提示词原文与节点源码）

### 问题 1｜场景／动作全丢 —— 新坑：上下文预算被参考图 token + 超长文本吃满（G08）

**触发句（结构层面，不是某一句写错）**：
- 本次提示词 **2670 字符 / 6816 bytes**，是模板已跑通样例（EP04 文戏，**1185 字符 / 2845 bytes**）的 **2.25 倍**。
- 段落分布：`subject_definitions` 698 + `summary` 240 + `retention_analysis` 257 = **1195 字符在前**；全部场景与动作在 `detailed_description`（1111 字符）**在后**。
- 节点源码 `comfy_extras/nodes_minimax_h3.py:267-268,301-309`：模板 `ref_image_size="max"`，参考图按**原尺寸**进 Qwen3-VL，且「Reference tokens ride through every sampling step」。本次三张为 2720×1536 双视图 + 1536×864 + 410×430，vision token 量远大于模板默认的三张小图。

**为什么是这个因果**：成片里人物造型（来自排在前面的参考图与主体定义）100% 正确，而排在其后的 5 镜动作、车库、车、蓝隼全部消失，模型退回「戴帽灰手套女性 + 一个水平台面」的自由补全（补全成钢琴）。这与「有效上下文被前部内容占满、后部文本权重归零」的预期完全吻合。8 步 / 0.5MP / DMaD 的低规格又放大了长文本遵循难度。

> 置信度：高（三条独立证据：长度倍数、段落分布、节点源码的 vision token 说明），但**未做硬截断的 token 级实测**，v2 需用最小样例验证，不能当已证定理写进规范。

### 问题 2｜琴身 `SALE CEEES` 金色伪字 —— A 型负向泄漏（既有型复发）

- **触发句**：`negativePrompt:` 里堆了 30+ 条「禁止汉字与伪汉字／禁止数字编号／禁止柱面编号／禁止车牌字符／禁止车标徽记／禁止标题卡／禁止Logo…」。
- **原因**：按避坑手册 A 型，否定句把「带字的牌面」概念放进潜空间；本地梅林模板把 `negativePrompt` 作为**同一段 Text 的末尾一行**喂进 text encoder，并没有独立的 negative 端口，否定项实际参与了正向 conditioning。P09/P15/P17 都栽在同一根因上，本次是复发。
- **改法**：v2 把 negativePrompt 压到 8 条、不写具体错误形态；文字类约束改用正向「所有表面纯材质、无字」。

### 问题 3｜无声段落出现中文乱语 —— G04 的一个未登记变体

- **触发句**：`overall_soundscape` 写「全程无人声、无对白、无旁白、无 BGM」，`negativePrompt` 又写「禁止人声对白与旁白」。
- **原因**：模板音轨来自 `VAEDecodeAudio`（节点 115/254），是**模型自生成**而非外部音轨；本地梅林没有喂参考音色，也没有静音开关。提示词层管不住自生成音轨，正如 G04「提示词层保不住的属性降级到后期层」。
- **改法**：本地梅林出片一律**后期替换整条音轨**为合成环境音（引擎/车门/金属/玻璃），不靠提示词。此条并入 G04 的适用边界，不另立编号。

## 四、泛化经验（§六 强制产出）

### G07｜新配置首次跑新任务类型，先过最小样例再上正式稿

- **一句话原则**：凡是**一套新工作流／新参数首次用于一类新任务**（如本地梅林第一次跑高速武戏），先用「1 镜 + 1 动作 + 同一套参考图」的最小样例确认提示词与参考图真的生效，再提交正式稿；否则失败时无法区分是「语法不生效」还是「模型能力不足」。
- **适用边界**：跨平台迁移、模板升级、任务类型从文戏切武戏、提示词结构大改时；同一配置下已跑通的同类型片段不强制。
- **可复制操作**：① 最小样例用正式稿的同一套参考图与同一模板，只把 `detailed_description` 换成一句场景 + 一个动作；② 抽 3 帧看「场景是否出现、动作是否发生、人物是否对」；③ 三项有两项不成立就先修配置/长度，**不许直接上正式稿**；④ 最小样例与正式稿都算生成次数，仍受一次反馈一次的闸门约束。
- **反例**：本次直接把 5 镜 2670 字符正式稿丢给从未跑过武戏的 0.5MP/8步 配置，8.3 分钟后才发现整段场景动作没进 conditioning。
- **归属**：操作型 → `视频制作技巧_David.md` §一；机制型 → 本文件 §六.7；资产型 → 片段 `开发说明.md` 验收口径。
- **来源案例**：本复盘第三节问题 1。

### G08｜提示词长度预算要连参考图像素一起算

- **一句话原则**：凡是参考图与文本共用同一个多模态上下文窗口的模型，**提示词预算 = 文本 token + 参考图 vision token**；切换任务类型时以「该模板已跑通样例」的总量为上限，不能只看文本字符数。
- **适用边界**：ref2va / 图生视频 / 多图参考类节点；纯文生视频不适用。
- **可复制操作**：① 记录模板默认提示词字符数作基线（本模板 1185）；② 新稿控制在基线 ±20% 内；③ 把**场景与动作放在文本前部**，主体定义压成短句后置；④ 参考图统一预缩放到生成分辨率量级（本项目 960×544），并去掉多视图拼图；⑤ `ref_image_size` 用 `match` 而非 `max`（改模板参数须用户确认，因「不改工作流」硬规则）；⑥ 否定项 ≤10 条。
- **反例**：本次 2670 字符（2.25× 基线）+ 2720×1536 双视图 + `max` 模式，人物锚生效而后半段 5 镜全丢。
- **归属**：操作型 → David §一/§五；机制型 → 避坑手册 §一新增说明；资产型 → `上传包_v2/` 预缩放图。
- **来源案例**：本复盘第三节问题 1、第二节核查表。
