## 四、本轮新坑与泛化经验（§六 强制产出）

### G09｜提交成功拿到 taskId 后，本地轮询进程被超时／断连杀掉 ≠ 生成失败

- 首次提交脚本已上传三图并打印 `taskId`，但本地轮询被命令超时 `SIGTERM`；单次查询显示服务端 `RUNNING`。
- 若误判成「没生成」而重跑提交脚本，会一次反馈烧两份额度并绕过闸门。
- 修法：提交与轮询拆成两个脚本，轮询脚本只收 taskId、不含提交代码；异常退出先查状态，`RUNNING` 就只续轮询。已落 `resume_ep06_6-1a_jinyu_v1.py`。
- 归属：机制型 → 自审规范 §六.7；操作型 → David §五；资产型 → resume 脚本。

### G10｜提示词长度基线按「具体工作流／配置」分别登记，不能跨平台套用

- 本地梅林 0.5MP/8步 基线 1185 字符；云端金鱼 1.5MP/12步 已跑通 4378–4940 bytes，硬上限 5000。
- 切链路先查目标链路近 3 个 SUCCESS 回执的 `promptBytes`，再核标签格式差异（云端无 `negativePrompt` 段）。
- 归属：机制型 → 避坑手册 §一维护说明；操作型 → David §一；资产型 → 片段开发说明参数表。

### G11｜Windows 上走 Schannel 的 curl 必须关闭证书吊销检查

- 报 `CRYPT_E_REVOCATION_OFFLINE (0x80092013)`，导致 `--check` / `get_node_info` / 提交 / 下载整条链以「Get node info failed: None」失败；易被误判成密钥失效或余额不足。
- 确诊 `curl --ssl-no-revoke` 返回 200；修法用 `subprocess.run` 包装器统一注入该参数 + UTF-8 容错解码，不改全局 skill 库。
- 归属：操作型 → David §五；资产型 → 提交脚本包装器。

### G12｜账户状态接口的 `remainCoins=0` 不代表任务不能提交，要看结算模式

- 提交前 `--check` 返回 `no_balance`（`remainCoins=0` / `remainMoney=-0.0130`），但 `remainPoint=1241`；任务实际被受理并 `SUCCESS`，回执 `settleMode=POINT`、`chargedPoint=82.45`，**金币为 0 也跑通了**。
- 一句话原则：**凡是平台有多种结算货币，提交前的余额判定不能只看单一字段**；账户状态接口的 `no_balance` 只作提示，不作「禁止提交」的硬断言。
- 适用边界：云端生成 API 的账户状态接口；本地出片不适用。
- 可复制操作：① 提交前记录 `remainCoins / remainMoney / remainPoint` 三个字段，别只看第一个；② 余额类失败立即停但仍允许单次提交试探（被拒不扣费）；③ 提交脚本把 `balance/insufficient` 列为 fatal 不重试，避免队列重试重复扣费；④ 出片后以回执 `usage.settleMode` / `chargedPoint` 为准记账，不按预估金币数记。
- 反例：看到 `no_balance` 就放弃云端链路、改走本地，或因担心重复扣费而不敢提交。
- 归属：机制型 → 自审规范 §六.7；操作型 → David §二「RunningHub 运行设置」；资产型 → `RH任务回执_金鱼_EP06_6-1a_v1.json` 的 usage 字段。
- 来源案例：本复盘开头结算信息。

### G13｜无对白片段不绑音频槽 ≠ 成片静音，先测再决定是否后期补音轨

- 本段 0 台词、`AUDIOS=[]`、三个 `LoadAudio` 槽保持 `None`（P02 先例）；出片后仍有 AAC 32kHz 立体声音轨，逐秒 RMS −43.6 ～ −15.8dB，10–11s 砸车 / 12–13s 砸地出现峰值，ASR `segments=0`。
- 一句话原则：**「要不要后期替换整条音轨」由出片后的音轨体检决定，不由「有没有绑音频槽」推断**；G04 的降级动作只在体检不通过时才执行。
- 可复制操作：① 无对白片段默认不绑音频槽，避免音色参考诱发乱语；② 出片后跑 `ffprobe` 查流 + 逐秒 RMS + 离线 ASR 三项；③ 无音轨／纯静音／有人声乱语，任一项命中才做合成环境音替换；④ 三项都过就直接交付原音轨，省一次后期。
- 反例：本地梅林 v1 因自生成音轨出现 3 段中文乱语，就推断所有「不喂音色」的链路都会静音或乱语，直接给每段都排后期替换。
- 归属：操作型 → David §九「音效响度」；机制型 → 自审规范 §六.7；资产型 → `check_ep06_6-1a_jinyu_v1.py` 音轨体检段。
- 来源案例：本复盘 §一第 7、8 项。
