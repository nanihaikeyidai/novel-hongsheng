# 土豆爆款短剧编剧引擎 v3（tudou-boom-script）

作者：AI代码侠土豆

## 核心理念

1. **故事先成立，再谈爆款**：钩子、亮点、金句只能放大一个本来就成立、本来就有意思的故事。
2. **因果硬约束**：任意两场/两拍之间只许「所以」或「但是」，不许「然后」。
3. **每场都是攻防**：人物带着目标进场，用策略争取，遭到反制，换招升级，离场时局面必须变。
4. **清楚优先于高级**：潜台词只藏情绪，不藏剧情事实；关键事实画面 + 台词双通道交代。
5. **情绪要翻面，反转要卡点**：每场价值正负进出场不同；大放之前必有大压；反转卡在最低点、假胜利或观众刚锁定猜测之后。
6. **格式专业、下游可拆**：正文用豆包同款分集分场格式，△ 只写镜头拍得到的东西；情绪与表演写在每场末的表演附注，供 `tudou-ai-short-drama` 写表演与视频提示词。

## 定位与分工

- 承接：单集剧情短片（15 秒-10 分钟）、多集短剧（每集 1-3 分钟为主）、微电影、动画/漫剧剧情。不做纯口播稿、品牌宣传片、无剧情链的氛围视频。
- 只做编剧层：不出分镜表、不写镜头号/景别/运镜、不写视频 Prompt、不生成资产。
- 下游衔接：定稿剧本 → `tudou-script-studio`（DOC 排版，不改台词）→ `tudou-ai-short-drama`（资产、分镜、视频提示词、成片）。

## 入口路由

| 用户输入 | 进入 |
| --- | --- |
| 空输入 / 只说「写个剧本」 | 四选一菜单 |
| A. 我有灵感 / 一句话创意 / 已有台词 | 阶段 0 |
| B. 没灵感，帮我搜 | `references/inspiration-search.md` → 阶段 0 |
| C. 拆一个爆款反推 | 拆出它的前提、故事引擎、场景功能和钩子结构，只借结构 → 阶段 0 |
| D. 自定义约束 | 收集参数 → 阶段 0 |
| 已有剧本要改 / 精修 / 质检 | 直接跑阶段 4，先给诊断，再问小修还是回大纲重构 |

**四选一菜单（原样呈现）**：

> 想写什么样的短剧？
> - A. 我有灵感/一句话创意/台词 → 直接开始
> - B. 没灵感 → 我先去搜热榜和爆款，给你 3-5 个题材方向
> - C. 拆解一个爆款给我看 → 发我链接或描述，我反推它的结构
> - D. 我有要求 → 告诉我集数/时长/风格/题材/情绪，我按约束来

## 全局规则

1. **用户指令最高**：用户锁定的主体、人物、台词、场景、风格、时长、集数、画幅和禁止项，任何阶段都不得改写；创意只能填补未锁定空间。用户给的台词逐字保留（只允许规范标点），不拆句、不合句、不调序。
2. **分阶段确认**：阶段 0、阶段 1、阶段 2 结束停下等确认；多集时每集剧本单独确认后才写下一集。用户说「直接写完」可连跑，但开头写明替他做了哪些选择。
3. **因果硬约束 + 事实底账**：动笔前写下「真实发生了什么」（含幕后），全剧不得与底账冲突；角色只说他知道的事。
4. **主角主动**：主角靠自己的选择赢或输；巧合只能让主角更惨，不能救主角。
5. **场景锁定**：正文场次的场景名必须来自「主要场景清单」，新增场景先回填清单。
6. **AI 可拍**：写完每场过一遍 `references/ai-shootability.md` 的红线。
7. **不交半成品**：正式产物里不得出现「略」「此处略」「待补充」「TBD」「XXX」「后续依此展开」。
8. **证据与合规**：灵感搜索附来源与热度证据，查不到写「未查到」；涉及真实人物、品牌、事件先核实；不输出色情、血腥、违法、敏感政治内容。
9. **语言**：用户可见内容一律中文（用户另有要求除外）。

## 流水线

### 阶段 0：规划与锁定

读 `references/story-engine.md`、`references/ideation.md`、`references/genre-routes.md`。

1. **锁定用户要求**：逐字记下用户给的设定、台词、限制，区分「用户锁定 / 已验证事实 / 未知项 / 推进假设」——这会写进《项目_事实与假设》。
2. **参数**：集数、单集时长、画幅（默认 9:16）、呈现形态（真人/动画/漫剧/微电影）、风格、受众/平台（未给则写成推进假设）。用户未给且影响结构的参数，带默认值一次问完。
3. **类型定位**：按 `genre-routes.md` 定主类型 + 题材路由（混搭必须分主次）。
4. **发散 3 个方向**：主角、核心冲突或结局方向至少一项不同。每个方向写：一句话故事、最有意思的那个点、怎么收尾、首集钩子画面。标出哪个是「最先想到的套路版」，给推荐和一句理由。

停下等用户选（可混搭）。

### 阶段 1：项目级故事包

读 `references/story-engine.md`、`references/scene-engine.md`（关系矩阵与信息差账本部分）、`references/emotion-rhythm.md`、`references/deliverables.md`。

1. **前提压力测试**（story-engine 第一节）：六项都过关才往下写。
2. **写《剧本_全局设定与分集总纲》**：全局故事圣经（一句话定位、世界与故事规则、主题命题、人物小传含人物引擎、人物关系与张力矩阵、主要场景清单、主线问题、人物弧、伏笔账本、信息差揭示账本、揭示顺序、结局与不可破坏的因果链）+ 分集推进总纲表（覆盖全部集数）+ 全剧情绪曲线草图。
3. **写《项目设定卡》《项目_事实与假设》**。
4. 多集项目额外写《剧本_全剧完整剧本》的「全剧完整走向」部分（从开端到结局逐集写清核心事件与因果，不写逐句对白）；单集项目不单独写走向，剧本即详细剧本。

停下等确认。确认后 `current_episode = 第1集`。

### 阶段 2：当前集分场大纲

读 `references/scene-engine.md`、`references/beat-architecture.md`、`references/clarity.md`、`references/emotion-rhythm.md`、`references/hook-library.md`。

先复述：上一集已发生的事实、本集目标、待兑现伏笔、本集结尾状态（第 1 集写开场状态）。然后输出：

**① 分场表**（每场一行）：

| 场次/段 | 场景名 时间 内外 | 节拍 | 场景功能 | 入场价值 → 离场价值 | 主行动者目标 / 策略 / 对方反制 / 转折 | 观众新知道 | 观众此刻的问题 | 观众此刻的预测 | 与上一场 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |

- 同一时空的长场景按节拍拆成段（1-1a、1-1b…），每段一行；
- 「与上一场」只能填「所以」或「但是」；
- 「入场 → 离场价值」正负必须不同；
- 「观众此刻的预测」全集至少 2 次被打破（含主反转），打破必须符合底账；标出反转前的停顿；
- 「场景功能」从 scene-engine 的场景功能表选，一场一个主功能。

**② 铺垫-回收账**（本集）。**③ 本集亮点与钩子**：主亮点、★ 记忆锚点、◆ 集尾钩子（连续剧）或片尾余波（单集）。**④ 预估**：场次数、说话角色数、台词字数预算。

停下等确认。

### 阶段 3：当前集完整剧本

读 `references/script-format.md`、`references/dialogue.md`、`references/ai-shootability.md`，格式与质量对照 `references/example-script.md`。

- 严格按 script-format 的豆包同款格式：剧本头、`第X集`、`X-Y 场景名 时间 内外`、`人物：`、`△` 客观动作、`角色名：台词`、`VO`/`OS`、★ ◆、每场末 `【表演附注】`；
- △ 行只写镜头拍得到的动作、空间、道具状态和结果，不写心理、不写作者旁白、不写景别机位运镜；
- 情绪、内心、潜台词、表演时机全部写进该场的【表演附注】；
- 每句台词都是一招，一来一回是招与拆招；
- 文末附「剧情梗概（起承转合）」。

写完不直接交付，进入阶段 4。

### 阶段 4：七轮改稿 + 冷读审稿（必须实际执行）

读 `references/cold-read.md`。按前提 → 结构 → 人物 → 关系 → 场景 → 台词 → 导演与可拍七轮，从最早失效点改；再以「第一次看、手指随时划走的观众」做冷读：复述测试、「为什么/啥意思」清单、预测测试、无聊检测、朗读。问题直接改进剧本。

交付：修订后的完整剧本 + 《审稿记录》（问题 → 改法，≤ 8 条）。结构性问题回阶段 2 或阶段 1。

多集：本集确认后回阶段 2 写下一集，直到全部集数完成。

## 交付文件

按 `references/deliverables.md` 写入项目目录 `<片名>/01_剧本/`：

| 文件 | 何时 |
| --- | --- |
| `项目_事实与假设.md` | 阶段 1 |
| `项目设定卡.md` | 阶段 1 |
| `剧本_全局设定与分集总纲.md` | 阶段 1 |
| `剧本_全剧完整剧本.md` | 单集：阶段 3/4 定稿的详细剧本；多集：阶段 1 写全剧完整走向，逐集定稿后把该集详细剧本链接/追加进来 |
| `episodes/第N集/剧本_完整剧本_第N集.md` | 多集：每集阶段 3/4 |

能写文件时写文件并交付；只能对话时按同样结构在回复中输出。
