# 交付文件规范（阶段 1、3、4）

## 一、目录

```text
<片名>/01_剧本/
├── 项目_事实与假设.md
├── 项目设定卡.md
├── 剧本_全局设定与分集总纲.md
├── 剧本_全剧完整剧本.md
└── episodes/            （仅多集）
    ├── 第1集/剧本_完整剧本_第1集.md
    └── 第2集/剧本_完整剧本_第2集.md
```

能写文件时按此落盘并交付；只能对话时按同样结构在回复里输出。修改已确认文件时保留旧版（文件名加 `_r1` 等），不覆盖。

## 二、《项目_事实与假设》（内部依据，阶段 1）

```markdown
# 项目_事实与假设
项目：<片名>　版本：r1

## 用户核心要求与限制（locked）
- 逐字记录用户给的设定、台词、时长、画幅、风格、禁止项……

## 已验证事实（verified）
- 用户确认过的选择、检索核实过的真实信息（附来源/日期）

## 未知项（pending）
- 还没定、但会影响剧情的点；没有写「无」

## 推进假设（assumed）
- 用户没说、我替他做的选择，例如平台、受众

## 策略选择（adopted）
- 主类型 / 题材路由 / 主机制 / 辅助机制 / 亮点支柱 / 风格合同
- 台词证据链：关键事实 → 前置铺垫 → 可见证据 → 揭示场次 → 后果
```

## 三、《项目设定卡》（给用户审的一页纸，阶段 1）

```markdown
# 项目设定卡 · <片名>
## 一句话定位
## 世界观与故事规则
## 人物与关系（表：角色｜年龄/身份｜形象锁定｜关系与功能）
## 主要场景（表：场景｜时间/内外｜空间要点）
## 声音主体（谁说话、旁白有无、是否用 BGM）
## 视觉方向（风格机制 + 排除项）
## 禁用项（不得改动的台词、形象、空间、设定）
```

设定卡是《全局设定与分集总纲》的用户可读投影：改设定卡里的事实时，先改总纲，再同步设定卡。

## 四、《剧本_全局设定与分集总纲》（阶段 1，项目事实源）

固定两个一级章节：

```markdown
# 剧本_全局设定与分集总纲

## 全局故事圣经
### 一句话定位
### 世界观与故事规则（本剧独有的规则/母题，写清它如何反复制造选择）
### 主题命题（价值 A vs 价值 B、反例、高潮选择、结局证据）
### 人物小传（每个主要角色，格式见下）
### 人物关系与张力矩阵（scene-engine 第三节格式）
### 主要场景清单（script-format 第七节格式）
### 主线问题（观众带着什么问题看下去）
### 人物弧（开场状态 → 触发事件 → 结局状态，写清弧线证据）
### 伏笔账本（伏笔｜埋设｜揭示｜回收）
### 信息差揭示账本（scene-engine 第四节格式）
### 揭示顺序（按观众得知的先后列出）
### 结局与不可破坏的因果链（因为…所以…但是…，任一环缺失都会破坏故事）
### 全剧情绪曲线（核心价值 + 每集/每场 ＋/－ 走向）

## 分集推进总纲
| 集号 | 集名 | 本集目标 | 阻力 | 策略变化 | 核心事件 | 阶段兑现 | 结尾状态 | 下一钩子 |
|---|---|---|---|---|---|---|---|---|
```

单集项目总纲保留一行「第1集」。超过 10 集时在总纲前写一句漂移风险说明：后续集以本总纲和人物弧为锚，逐集复核。

**人物小传格式**：

```markdown
#### 角色名（主角 / 对手 / 配角）
- 一句话定位：年龄 + 身份 + 人设标签
- 形象锁定：发型、脸型/体型、标志性服装与识别物（给下游做资产）
- 外在欲望：本剧中可观察、可失败的目标
- 内在需要：必须学会、承认或放下的东西
- 错误信念：曾保护他、如今伤害他的判断
- 优势与阴影：同一性格如何既帮忙又惹祸
- 秘密 / 底线 / 越界选择：哪个节点逼他跨过底线
- 行为签名：说话方式、口头禅、施压/回避/撒谎的习惯（决定台词声音）
- 弧线：开场 → 动摇 → 结局，写清触发事件
- 固定音色：年龄感 + 音高质感 + 语速 + 句尾习惯
```

对手/对立力量必须写「合理性动机」；不需要人格化反派的作品写清对立力量如何被理解、绕过或承受。

## 五、《剧本_全剧完整剧本》与分集剧本

- **单集项目**：本文件就是阶段 3/4 定稿的详细剧本。结构：剧本头 → 第1集正文（含每场表演附注）→ 剧情梗概（起承转合）。
- **多集项目**：阶段 1 先写「全剧完整走向」——从开端到最终结局逐集写清核心事件、关键行动、核心台词意图、伏笔埋设与回收、高潮与最终状态（不写逐句对白）；每集详细剧本写在 `episodes/第N集/剧本_完整剧本_第N集.md`，定稿后在本文件末尾登记链接。

**分集剧本文件结构**：

```markdown
# 剧本_完整剧本_第N集
（剧本头，多集可只在第1集写全，后续集写「接第N-1集」）
## 本集梗概：本集目标、阻力、策略变化、高潮、结果、下一钩子
## 本集人物状态：开场/结尾的关系、认知、服装、伤痕、道具归属
第N集
N-1 场景名 时间 内外
……（正文 + 每场表演附注）
## 剧情梗概（起承转合）
```

**剧情梗概（起承转合）**：3-4 段，覆盖起点与主角处境、冲突登场、升级与转折、高潮与落点；写清主角动机、对立面的具体手段、主角关键抉择、结局形态。

## 六、字数门禁

每集正文（不含表演附注和梗概）有效字数下限：`max(120, min(800, 单集秒数 × 4.5))`。低于下限说明场次或动作没写全。字数达标不等于合格，仍须过阶段 4。

## 七、多集逐集规则

1. 阶段 1 一次锁定全部集数的总纲、人物弧、伏笔账本和最终结局，不提前写各集详细剧本；
2. 每次只细化当前集：先复述上一集已发生事实、本集目标、待兑现伏笔，再写分场大纲 → 剧本 → 改稿；
3. 当前集确认后才写下一集；每集完成后对照总纲复核人设、因果、伏笔方向，发现漂移只修当前集，或回到真正受影响的总纲条目；
4. 每集必须有本集兑现（信息、关系、爽点或情绪），集尾钩子不能吞掉本集回报；
5. 用户改动已确认内容时，先列出受影响的集和文件，只改受影响部分。
