# 七轮改稿 + 冷读审稿（阶段 4，必须实际执行）

自评最大的问题是「自己写的自己都懂」，于是全部通过。本流程分两段：先按七轮从最早失效点改稿，再换成第一次看的观众冷读。**每一步都要写出具体产出，不允许只写「通过」。**

## 第一段：七轮改稿

依次执行。前一轮有阻断问题时，不提前润色后一轮。每轮记录：阻断问题 → 证据位置（场次）→ 最早失效点 → 修订动作 → 连带影响。

| 轮 | 查什么 | 对照 |
| --- | --- | --- |
| 1 前提轮 | 卖点、主角、代价、反讽、不可逆选择是否成立 | story-engine 前提压力测试 |
| 2 结构轮 | 因果链（所以/但是）、升级、伏笔回收、反转公平、高潮是否由前文造成；情绪曲线是否每场翻面 | story-engine、emotion-rhythm |
| 3 人物轮 | 每次行动是否符合欲望、错误信念、资源与代价；主角是否主动；对手是否有道理、不降智 | deliverables 人物小传 |
| 4 关系轮 | 核心关系是否因具体事件变化，矩阵变化能否回指场次 | scene-engine 第三节 |
| 5 场景轮 | 每场入场→离场价值是否改变；目标、策略、反制、转折是否齐全；场景功能是否明确；有无可删的空转场 | scene-engine 第一、二节 |
| 6 台词轮 | 每句是招、招与拆招、声音指纹、潜台词不藏事实、用户台词逐字保留、传播句有支撑 | dialogue |
| 7 导演与可拍轮 | △ 无心理/作者旁白/镜头词；关键信息能被动作、空间、声音表达；过 AI 红线；格式合规 | script-format、ai-shootability |

## 第二段：冷读

以「第一次看、不知道总纲、手指随时要划走的观众」读一遍正文（不看附注）：

1. **复述测试**：三句话复述「谁想要什么 → 遇到什么 → 结果怎样」，对照总纲一句话定位。对不上 = 剧本没把故事讲出来。
2. **「为什么 / 啥意思」清单**：至少列 5 个观众会冒出的疑问，每条标【悬念】（写明在哪场回答）或【困惑】（必须修：补交代、改台词、加画面或删掉引起困惑的东西）。列不出 5 条说明没在真冷读。
3. **预测测试**：逐场遮住下一场，写「我猜接下来会……」。主反转被猜中 → 必须改（换卡点、加诱饵答案、把真线索藏到注意力之外）；反转后有没有留一拍反应再推进？
4. **无聊检测**：指出最弱的一场（最可能划走处）并改掉；最有意思的那个点在开场就露出来了吗？
5. **朗读**：按演出速度念对白，挑出最假的 3 句（书面语、说教、没招、各说各话、金句腔）给出改后版本；遮住名字看能否分清角色。

## 硬指标

| 项 | 标准 | 实测 |
| --- | --- | --- |
| 开场 | 主角已在麻烦中，有可见冲突，无背景介绍 | |
| 开场四件事 | 90s 约 15 秒内、60s 约 10 秒内交代清 | |
| 双通道 | 关键事实画面 + 台词都有 | |
| 字数 | 正文 ≥ max(120, min(800, 秒数×4.5))，台词量在预算内 | |

| 格式 | 符合 script-format 九项自查 | |

## 交付

1. 发现的问题**直接改进剧本**，交付修订后的完整剧本；
2. 附《审稿记录》：「问题 → 改法」，≤ 8 条，只写真改了的；
3. 结构性问题——复述不出、因果链断 2 处以上、主角被动或靠巧合获胜、最有意思的点不存在——回阶段 2（本集）或阶段 1（全局），不在正文上打补丁；
4. 定稿后提示衔接：`tudou-script-studio`（文学剧本 DOC）→ `tudou-ai-short-drama`（资产、分镜、成片）。

## 改用户已有剧本时

同样跑两段，先给《诊断》（按严重度：故事不成立 > 讲不清 > 因果断 > 没意思 > 台词假 > 格式），再问用户：小修正文，还是回大纲重构。用户要求转成本技能格式时，按 script-format 转写，用户台词逐字保留。
