## 两套素材编号严格分离

- `@图片N`、`@音频N` 是上传槽位和素材清单编号，只能出现在主提示词外部的“素材映射”或工作流绑定记录中。

- 外部映射必须明确写出槽位到 H3 标签的对应关系，例如：`@图片1 → <Picture 1> → <Subject 1> 陆沉`、`@音频1 → <Audio 1> → <Subject 1> (S1) 的音色参考`。
- 标签按当前实际绑定顺序重新编号，全文含义固定；禁止沿用旧编号、跳号、重号、同号异义或混用 `@图片N` 与 `<Picture N>`。

## Ref2VA 六段结构强制顺序

《红绳》文戏模板用于先完成剧情拆分、对白预算、口型、声线和连续性设计；写入工作流的最终主提示词必须再转换为下列 H3 Ref2VA 六段结构，不得把文戏模板的中文顶层标题直接代替 H3 段落标签。

每个最终主提示词必须包含且只按以下顺序排列：

1. `subject_definitions:`
2. `summary:`
3. `retention_analysis:`
4. `detailed_description:`
5. `overall_soundscape:`
6. `non_diegetic_music:`

六段正文使用英文；中文对白保持中文并写入 `<d>[Chinese] ...</d>`。无BGM时固定写 `non_diegetic_music: N/A`。

写入 `timeline_data.segments[N].prompt` 的内容必须从 `subject_definitions:` 第一行直接开始，并在 `non_diegetic_music:` 段结束。素材映射、Markdown 标题、解释文字、审核备注、`@图片N`、`@音频N` 和代码围栏只能保存在主提示词外部，不得与六段正文一起提交给 H3。

## 故事板只读文字化门禁

- 故事板／六宫格／九宫格必须在本地实际查看，用于提取镜头顺序、动作节拍、机位、世界坐标、人物朝向、移动路径和首尾状态。
- 默认禁止把故事板图片上传到 RunningHub 或绑定为 `<Picture N>`。不得让 H3 从宫格像素自行理解分镜；宫格线、字幕、编号、箭头、错误湿衣、错误人物和不稳定构图会污染成片。
- 故事板内容必须先改写为自包含的 `detailed_description`。即使完全移除故事板图片，文字也必须独立说明摄影机在哪里、朝哪个方向、人物从哪里出发、正对谁、经过什么路径、在哪里接触以及如何稳定收束。
- RH 图片输入默认只保留当前镜头真正需要的独立资产：人物图、场景图、道具图和独立首帧／末帧。独立首帧必须由人物／场景参考和文字站位生成，不得直接裁切、拆格或扩展故事板面板充当首帧。
- 只有用户明确要求“把故事板作为图片参考”时才可上传；即便上传，也必须声明只参考镜头规划，不继承文字、边框和视觉身份。

## 空间与机位文字化规则

- 先写不随镜头变化的世界轴线，再写机位。推荐格式：`门口 -> 移动人物 -> 过道 -> 目标人物/机位`。
- “镜头拍到人物正面”不等于“人物面对观众”。必须同时写清人物的实际目标与机位关系，例如：`机位在林晓肩旁朝门口反拍；苏婉始终正对并注视林晓，林晓紧邻镜头，因此画面能看到苏婉正面。`
- 过肩镜头必须写明谁的肩后、谁在近景、镜头朝哪个固定锚点；移动人物的胸口、肩、脚尖、视线和运动路径应指向同一目标。
- 多人走位先固定不移动人物的位置和占位半径，再只允许剧情指定人物改变世界坐标。镜头切换不得解释为人物换位。

## 标签用途

- `<Subject N>`：角色、怪兽、场景、道具、服装、特效等会在目标视频中复用的可见内容。
- `<Picture N>`：只在图片本身承担首帧、末帧、关键帧、具体构图锚点或故事板规划时单独定义。只用于人物/场景身份来源的图片，应在对应 `<Subject N>` 定义中引用，不重复建立无用途的图片条目。
- `<Video N>`：原视频编辑、续写或整体镜头节奏参考。
- `<Audio N>`：音色、语速、情绪、节奏或音频信号参考；只参考音色时必须明确不复制原台词和背景噪声。
- `(S1)`、`(S2)`：按目标视频中第一次真实发声的顺序分配并全文固定。人物说话时写 `<Subject N> (Sx)`。
- `<d>[Chinese] ...</d>`：所有中文对白、OS或画外音的逐字内容；普通动作描述中不得用引号另写一份台词。

### 对白标签唯一性（强制）

- 每个 `<Audio N>` 必须在 `subject_definitions` 中单独占一行并绑定唯一说话人，例如：`<Audio 1> is the voice-timbre reference for <Subject 1> (S1).`
- 每次真实发声只允许出现一次说话人标签。正确格式：`<Subject 1> (S1) ... says, <d>[Chinese] 你没事吧？</d>`。
- 禁止重复格式：`<Subject 1> (S1) ... (S1) <d>[Chinese] 你没事吧？</d>`；同一事件重复 `(Sx)` 容易造成口型、声线和说话人异常。
- `(Sx)` 只出现在音频绑定和真实发声事件中；禁止写入 `retention_analysis`。
- 对白不得在 `summary`、`overall_soundscape` 或禁止项中再次逐字重复。`overall_soundscape` 只概括“几条对白、谁先谁后、环境音”，不复述台词。
- 问答必须显式写前一句说话者闭口后，后一人才能发声；同一时刻只有一人张嘴。

## 素材描述必须重新生成

- 每次重新绑定、增删或调换素材，都必须重新查看实际素材并重建 `subject_definitions`、`summary` 与 `retention_analysis`。
- 每项素材写清唯一职责、必须继承项、不继承/允许变化项和出现镜头。
- 人物图负责“谁”，场景图负责“在哪里”，故事板负责镜头顺序与节拍，首尾帧负责具体画面锚点，动作视频负责“怎么动”，镜头视频负责“怎么看”，音频负责指定的声音属性。
- 参考图与故事板冲突时参考图优先；无对应参考图且内容为镜头必需时，才用故事板补足。
- 故事板、首帧或参考图内的字幕、编号、箭头、宫格线和制作文字不得继承。

## `negativePrompt` 强制字段

- 每个片段的 `negativePrompt` 必须单独生成且不得为空；主提示词中的禁止句不能替代此字段。
- 固定基础项：`subtitles, captions, on-screen text, Chinese characters, title cards, speech bubbles, UI, watermark, logo`。
- 按当前片段追加身份漂移、错误人物、错误场景、空间翻转、道具复位、环境复原、肢体错误或剧情越界等高风险项；不复制上一片段的动态禁项。
- `timeline_data.segments[N].negativePrompt` 与 `timeline_data.batchWorkspaces.r2v.segments[N].negativePrompt` 必须完全一致。

## 提交前硬校验

- 六个段落标签齐全且顺序正确。
- 所有 `<Subject N>`、`<Picture N>`、`<Audio N>`、`<Video N>` 均已定义并在全文保持同义；无未解析标签、重号或同号异义。
- 外部素材槽位与 H3 标签一一对应，素材数量和描述数量一致。
- 所有对白均有稳定 `(Sx)`，使用 `<d>[Chinese] ...</d>`，同一时刻只有一人说话并满足15秒对白预算。
- 主提示词第一行是 `subject_definitions:`，仅含六段 H3 正文；不存在 Markdown 标题、素材映射、代码围栏或附加顶层字段。
- 每个发声事件只有一次 `(Sx)`，不得匹配 `\(S\d+\)\s*<d>` 这类重复标签写法；`<d>[Chinese] ...</d>` 的数量与对白台账完全一致。
- 故事板已本地查看并完成文字化，但未作为 RH 图片输入；除非用户明确要求上传故事板。
- 时间线连续覆盖0–15秒；入点、动作链、出点与剧本、故事板和连续性台账一致。
- `overall_soundscape` 只包含人声、环境音和动作音；`non_diegetic_music: N/A`。
- `negativePrompt` 非空且两个片段数组同步。
- 新素材只追加为新片段，不覆盖已有素材；第二片段起 `continuityFromPrev=true`。
- 任一项失败时仅输出“未通过标签门禁”的草案，不得写入或提交 RunningHub。
