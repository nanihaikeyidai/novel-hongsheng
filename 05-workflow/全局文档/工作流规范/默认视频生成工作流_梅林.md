### 为什么是"两段式"而不是一张图里串起来

本机 16GB 显存，H3 UNET **19.53GB**、RelayVSR x2 **4.81GB**。同一张图串联会反复
全量换出/换入，表现为长时间停在 0 it/s（10-09 那次 B 组卡死 15 分钟就是这么来的）。
所以脚本在生成完成后先 `POST /free` 卸载 H3、等显存回到 ≥9GB，再提交 VSR 任务。
两段之间干净切分，实测稳定。

### 环境约束（重要）

`comfy-kitchen` 必须是 **0.2.39+spark.h3.sm89.cu130.1**：

- 梅林工作流的 `MiniMaxH3SparkAttentionSM89` 节点依赖 Spark 扩展，换官方包会直接报
  `ComfyUI Spark requires the comfy-kitchen Spark extension`
- 官方 0.2.41 的 RelayVSR 走原生 window_attention kernel，比 Spark 版快 2.35~3.05 倍，
  **但梅林会挂**。当前取舍：保梅林，VSR 走 `custom_nodes/comfyui-kitchen-window-attn-compat`
  垫片（纯 torch，数值等价，慢约 2.8 倍）
- 回滚命令（若被误升级）：
  ```bash
  "F:/Work-Fisher纯净包2026.8.7/python/python.exe" -m pip install --force-reinstall --no-deps \
    "F:/h3tmp/spark015/ComfyUI-Spark-H3/wheelhouse/comfy_kitchen-0.2.39+spark.h3.sm89.cu130.1-cp312-abi3-win_amd64.whl"
  ```
  换完必须重启 ComfyUI（`POST /manager/reboot`，约 40s 恢复）
- ⚠️ `requirements.txt` 仍钉 0.2.39，别直接 `pip install -r`
